Modelo de Prototipos

El modelo de Prototipos utiliza versiones preliminares del software para comprender mejor las necesidades del usuario antes de construir completamente el producto.

¿Qué es el modelo de Prototipos?

El modelo de Prototipos consiste en construir una versión inicial o simplificada del sistema antes de desarrollar completamente el producto definitivo.

Esta versión permite que el usuario observe cómo podría funcionar el software, revise las interfaces, pruebe algunas funcionalidades y dé su opinión.

La información obtenida permite mejorar los requisitos y reducir posibles diferencias entre lo que espera el usuario y lo que posteriormente desarrollará el equipo.

Clasificación principal

Clasificación

Metodología tradicional

Dentro de la clasificación utilizada en este proyecto se encuentra entre las metodologías tradicionales. Su principal característica es utilizar prototipos para comprender y validar los requisitos.

Objetivo principal

Su objetivo principal es reducir la incertidumbre cuando los requisitos del software no están completamente definidos, permitiendo que los usuarios conozcan una versión preliminar del sistema y proporcionen retroalimentación.

Características principales

Versión inicial

Se construye una representación inicial del sistema.

Validación

Permite comprobar si las necesidades fueron entendidas correctamente.

Retroalimentación

El usuario puede expresar cambios y nuevas necesidades.

Requisitos

Ayuda a descubrir requisitos que inicialmente no estaban claros.

Interfaz

Puede utilizarse para validar pantallas y formas de interacción.

Mejora progresiva

El prototipo puede modificarse utilizando los comentarios obtenidos.

Participación

Requiere interacción entre usuarios y desarrolladores.

Experimentación

Permite evaluar ideas antes de implementar la solución completa.

Tipos de prototipos

Prototipo desechable

Se crea para entender mejor los requisitos y evaluar diferentes ideas. Cuando se obtiene la información necesaria, el prototipo puede descartarse y comenzar el desarrollo definitivo.

Prototipo evolutivo

Comienza como una versión sencilla y se va mejorando mediante diferentes modificaciones hasta acercarse progresivamente al producto final.

Proceso general

01

Requisitos iniciales

Se identifican las principales necesidades conocidas.

02

Diseño inicial

Se prepara una propuesta básica del funcionamiento.

03

Construcción

Se desarrolla una primera versión del prototipo.

04

Evaluación

El usuario revisa y prueba el prototipo.

05

Retroalimentación

Se identifican cambios, errores o necesidades adicionales.

06

Modificación

El prototipo se ajusta utilizando los comentarios obtenidos.

07

Validación final

Se comprueba que los requisitos sean suficientemente claros.

08

Producto

Se desarrolla o completa el sistema definitivo.

Ventajas

✓ Facilita comprender los requisitos.

✓ Permite recibir retroalimentación temprana.

✓ Ayuda a validar interfaces.

✓ Reduce malentendidos con el usuario.

✓ Permite experimentar con distintas soluciones.

✓ Los usuarios pueden visualizar el sistema anticipadamente.

Desventajas

• Puede aumentar el tiempo de desarrollo.

• Pueden aparecer demasiadas modificaciones.

• El usuario puede confundir el prototipo con el producto final.

• Un prototipo rápido puede tener baja calidad técnica.

• Cambios constantes pueden afectar la planificación.

¿Cuándo utilizar Prototipos?

Es especialmente útil cuando los requisitos no están claros, cuando la interfaz tiene mucha importancia o cuando el usuario necesita visualizar el sistema antes de definir completamente sus necesidades.

¿Cuándo no utilizarlo?

Puede ser innecesario cuando los requisitos ya están completamente documentados y el producto es sencillo y conocido.

Ejemplo práctico

Aplicación móvil para reservas

Antes de desarrollar completamente una aplicación para reservar citas, el equipo puede crear pantallas básicas que permitan al cliente visualizar cómo se seleccionarán fechas, servicios y horarios. Con sus comentarios se modifica el diseño antes de construir la versión definitiva.

En conclusión

El modelo de Prototipos permite reducir la incertidumbre y mejorar la comunicación con el usuario. Su principal utilidad aparece cuando todavía existen dudas sobre los requisitos o sobre la forma en que debe funcionar el producto.
